# 구상채권 회수 예측 — 로컬 실행 파이프라인

코랩 노트북 4개(`코드/`)를 내 컴퓨터에서 바로 돌아가는 파이썬 스크립트로 옮긴 것.

| 확인 항목 | 팀 결과 (PDF) | 로컬 실행 |
|---|---|---|
| 공매 10월 test P50 오차 | 17.3%p | 17.317%p (같음) |
| 경매 219건 P50 오차 (보정 후) | 14.1%p | **14.50%p** — 아래 설명 |
| P10~P90 포함률 | 90% | 0.881 |
| 기준선 | 17.2%p | 17.153%p |

**학습 기간**: 팀 코랩은 최종 모델을 10월 공매까지 넣어 다시 학습했는데, 경매 219건 시험셋도 2026년 10월이라 기간이 겹침.
지금은 원래 설계대로 **2026-09-30까지만** 학습 (`step1_bid_model.py`의 `FINAL_TRAIN_END`). 그래서 219건 오차가 14.09 → 14.50%p로 조금 커졌지만, 이 숫자는 학습에 안 쓴 기간으로 잰 값이라 그대로 주장할 수 있음.
팀 모델로 재현하려면 `python step2_calibration.py --team-model` → 14.091%p (팀 결과와 같음).
219건 진단(실제가 P50 아래 64.8% · P10 아래 9.6% · P90 위 2.3%, 공장 +16.5%p · 상가 +9.5%p 과대)은 2단계가 `calib_out/calibration.json`의 `eval_auction`에 저장하고 시뮬레이터 경고에 그대로 씀.
이 과대예측을 보정해 넣고 싶다면 보정값은 10월 시험셋이 아닌 다른 기간(예: 9월 이전 경매)으로 정해야 함 — 지금은 경고만 띄우고 예측값은 고치지 않음.

## 1. 처음 한 번: 환경 준비

macOS
```bash
cd ~/Downloads/신보프로젝트
brew install libomp                      # LightGBM이 맥에서 필요로 하는 라이브러리
python3 -m venv .venv                    # 프로젝트 전용 파이썬 환경
.venv/bin/pip install -r requirements.txt
.venv/bin/python pipeline/run_all.py
```

Windows (명령 프롬프트 또는 PowerShell, libomp 설치 필요 없음)
```bat
cd %USERPROFILE%\Downloads\신보프로젝트
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python pipeline\run_all.py
```

> 범주형 피처(용도·구조·주용도…)는 학습 때 `model_meta.json`에 저장한 범주 목록의 번호로 직접 바꿔서 넣음 (파이썬·브라우저 같은 방식) → pandas 버전에 따라 예측이 바뀌던 문제는 없앰. 다만 pandas 3.x에서는 아직 돌려보지 않아 `requirements.txt`는 2.x로 둠. LightGBM은 4.6.0으로 고정.

## 2. 실행

```bash
cd ~/Downloads/신보프로젝트/pipeline
../.venv/bin/python run_all.py           # 1→2→3→4단계 전체 (약 20초)
../.venv/bin/python run_all.py 3         # 수집양식 엑셀만 바뀌었으면 3단계만
```

| 단계 | 파일 | 하는 일 | 결과 (`output/`) |
|---|---|---|---|
| 0 (선택) | `step0_auction_features.py` | 경매 사건 주소 → 공시지가·건축물대장. **경매 사건을 새로 추가했을 때만**. 인증키 필요 (`VWORLD_KEY`, `DATA_GO_KR_KEY`), 국내 IP | `auction_features.csv` |
| 1 | `step1_bid_model.py` | 공매 낙찰가 모델 (기준선·선형·LightGBM 비교, CQR) 학습·평가·저장 | `model_out/` |
| 2 | `step2_calibration.py` | 공매→경매 보정 계수 선택(9월 val) + 대구·경북 경매 219건 평가 | `calib_out/` |
| 3 | `step3_dividend.py` | 손계산 테스트 → 배당 계산 + 몬테카를로 1만 회 | `dividend_out/` |
| 4 | `build_dashboard.py` | 모델 나무·보정값·사례 49건을 HTML 한 파일에 넣음 | `회수시뮬레이터.html` |

### 새 물건 하나 예측하기

```bash
../.venv/bin/python predict_new.py --감정가 8462007760 --용도 공장·창고 \
    --시도 대구광역시 --시군구 달성군 --토지면적 11031.3 --건물면적 4434.6 --매각월 2026-10
```
선택 입력: `--공시지가`(㎡당 원) `--사용승인연도` `--지상층수` `--연면적` `--구조` `--주용도`. 모르면 빼면 됨.
용도는 `아파트 / 기타주거 / 상가·업무 / 공장·창고 / 대지 / 농지·임야` 중 하나.

## 3. HTML 회수 시뮬레이터

`output/회수시뮬레이터.html` 을 더블클릭해서 크롬으로 열면 됨. 서버·인터넷 없이 동작 (글꼴만 인터넷이 있으면 IBM Plex로 바뀜).

- **① 물건**: 감정가·용도·지역·면적·공시지가·건물 정보 → 브라우저가 LightGBM 나무를 직접 따라가 P10/P50/P90 예측
- **② 권리관계 · ③ 임차인**: 등기부·매각물건명세서 그대로 입력. 줄마다 배당 순위가 바로 표시됨
- **④ 신보 설정**: 일반채권자 / 가압류 날짜 / 근저당 날짜, 채권액
- **⑤ 가정값**: 집행비용률, 근저당 ÷1.2, 체납세금 시나리오
- **결과**: 회수액 중앙값·0원 확률·범위·회수율, 히스토그램, 신보 위치별 민감도, 손익분기 낙찰가, 배당표
- 위 선택 상자에서 팀이 수집한 실제 경매 49건을 불러오거나, "새 물건 입력"으로 직접 입력. 고친 내용은 그 브라우저에만 저장됨

**문서 자동 입력** (`dashboard/doc_parser.js`): 1단계에 PDF를 끌어다 놓거나 글을 붙여넣으면 감정가·용도·소재지·면적·공시지가·건물 정보·등기부·임차인·매각가·집행비용을 채움. 여러 파일을 함께 올리면 합쳐서 채움.
- 옥션원 인쇄 PDF: 표 위치까지 써서 정밀하게 읽음 (임차인 표 — 임차인별로 나눠 읽고 문건처리내역상 배당요구일도 반영, 집합건물 대지권, 근저당 일부이전은 원래 근저당 순위로, 건물·토지 등기부에 두 번 나오는 권리는 한 건으로, 경매개시결정의 청구금액은 금액 칸에)
- 그 밖의 양식(법원경매정보 인쇄본, 팀 가상 문서 등): 내용으로 판단 — "날짜 + 등기목적 + 금액" 줄은 권리, "감정가·매각가·소재지·물건 종류…" 옆 값은 물건 정보, "채권계산서·배당요구·교부청구"는 신고 내역
- 감정가가 없고 매각가만 있으면 예측 없이 그 매각가로 배당표만 계산
- 채권계산서 신고액은 메모로만 남김. 근저당 금액은 경매 청구금액이 있으면 그 값, 없으면 최고액 ÷ 1.2 (화면에 '추정' 표시)
- 글자가 들어 있는 PDF를 그대로 읽어 OCR보다 정확하고, 파일은 브라우저 밖으로 나가지 않음. 스캔 이미지 PDF는 지원하지 않음. PDF 읽기 도구(pdf.js 3.11.174)는 `dashboard/vendor/`에 있고 오프라인 파일에 함께 들어감.

왼쪽 메뉴: 입력이 끝난 단계는 초록 ✓, 아직이면 회색 숫자. 3단계는 임차인을 넣거나 "임차인 없음"을 체크하면, 5단계는 한 번 열어 확인하면 완료.

계산 엔진은 `dashboard/engine.js`, 화면은 `dashboard/app.html`. 파이썬과 같은 값이 나오는지 확인:
```bash
node dashboard/test_engine.js     # 손계산 T1~T10 · 낙찰가 예측 219건 · 배당표 49건 일치 확인
```

## 4. 가정값 바꾸기

- 신보 위치·채권액, 집행비용률, 근저당 ÷1.2, 청구금액 사용, 체납세금 시나리오·당해세 여부, 안분 후 흡수(ABSORB), 근저당 일부대위 규칙 → 프로젝트 맨 위 **`settings.json`** 하나. step3과 HTML(4단계에서 넣음)이 같이 읽음. 바꾼 뒤 `run_all.py 3 4`

## 6. 알아둘 점

- `data/auction_feat_cache.jsonl`(API 조회 캐시)은 최종본보다 오래돼서 10개 주소가 빠져 있음. 그래서 2단계는 팀의 최종 `data/auction_features.csv`를 씀. 0단계는 사건을 추가할 때만 인증키를 넣고 실행.
- 새 물건 예측에서 매각월이 R-ONE 표(2026-09까지)보다 늦으면 가장 최근 월의 지가변동률을 씀.
- **학습-예측 불일치 (선택 설정)**: 학습 데이터(온비드)에서 토지 물건의 건물면적은 0인데, 노트북은 경매 평가·새 물건 예측 때 빈칸으로 넣음 → 토지 예측이 평균 2.2%p 달라짐. 기본값은 노트북과 같게 `LAND_BLD_AS_ZERO = False` (`common.py`). `True`로 바꾸면 0으로 맞추고 경매 219건 오차 14.09 → 13.90%p.
- **배당 규칙 (노트북에서 바꾼 것)** — 파이썬(`step3_dividend.py`)과 JS(`dashboard/engine.js`)가 같은 규칙
  - 같은 날 근저당: 금액 비율 안분이 아니라 **을구 순위번호** 순서 (순위번호가 없으면 같은 순위로 안분)
  - **토지·건물 등기부별 배당**: 두 등기부의 근저당 순서가 다르거나 한쪽에만 있는 근저당이 있으면, 매각대금을 토지·건물 감정가 비율로 나누고 등기부마다 순위대로 배당. 공동저당은 각 부동산 경매대가 비율로 분담(민법 368조 1항), 경매대가 = 그 부동산 몫 − 집행비용 몫 − 그 부동산의 선순위(선순위 공동저당은 분담액) − 같은 순위 채권 몫(대법원 2001다66291, 2020다258893), 값이 맞을 때까지 반복 계산. 남은 돈은 그 등기부 근저당의 못 받은 몫부터 채운 뒤 일반채권으로
  - 가압류가 어떤 근저당보다 먼저면: 그 날짜부터 뒤의 권리를 한 풀에서 안분한 뒤 담보권·세금이 후순위 몫을 흡수 (안분 후 흡수). **세금·공과금은 앞선 가압류 몫에서도 흡수.** `ABSORB=false`면 노트북 규칙
  - 세금·공과금은 일반채권보다 앞. 근저당과의 순서는 법정기일을 몰라 압류일로 대신 정함(화면·메모에 경고). 금액 모르는 세금은 체납세금 시나리오, `TAX_FIRST=true`면 당해세로 보고 근저당보다 먼저
  - 소액임차 1/2 한도 = (매각가 − 집행비용) × 한도비율
  - 경매 청구금액: 임의경매 신청 채권자(신보 제외)의 근저당에 순위대로, 각 근저당의 (최고액 − 신보 일부이전 몫)까지 채움. 넘는 금액은 담보 밖. 메모의 '양도 전·양도인·X 근저당 양수·변경 전 상호 X'도 같은 채권자. 이름으로 못 찾고 근저당권자가 한 곳뿐이면 그 근저당에 연결하고 '확인 필요'. 강제경매 신청 채권자의 가압류가 1건이면 청구금액
  - 청구금액이 없는 근저당: (최고액 ÷ 1.2) − 신보 일부이전 몫, 화면에 '추정'. 은행 행에 신보 몫을 빼고 넣은 수집양식은 메모의 '원래 채권최고액 N' / '원래 N억'을 최고액으로 씀
  - 근저당 일부이전(신보 대위변제)은 새 근저당이 아니라 원래 근저당 순위 안의 신보 몫. 원래 근저당 찾기: 같은 접수일 → 같은 순위번호 → 비고의 '을구 N번' → 등기목적·메모의 은행 이름. 은행과 비율로 나눌지 은행이 먼저인지는 `PARTIAL_SUBROGATION` (기본 비율, 멘토 확인 필요. 시뮬레이터 5단계·배당표에서 바꿈)
  - **신보 채권** = 근저당(일부이전 + 신보 자기 근저당) + 신보 가압류 중 근저당 금액을 넘는 부분만 일반채권 한 줄 (같은 구상채권으로 보고 중복 제거). 회수율 분모도 이 합계. 신보 자기 근저당은 신보 임의경매 청구금액이 있으면 그 값(최고액까지)
- **수집양식 엑셀의 선택 열** (없거나 비어 있으면 지금처럼 토지·건물을 합쳐서 계산하고, 메모에 '토지만·건물만'이 있으면 경고)
  - ⑩ 등기부 권리 시트에 `등기부(토지/건물)` 열: 토지 / 건물 / 토지·건물. 공동담보가 등기부마다 접수일·순위번호가 다르면 토지 줄과 건물 줄을 따로 넣으면 한 건으로 합쳐 등기부별 순위로 씀
