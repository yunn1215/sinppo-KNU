# 구상채권 회수 예측 — 최종 모델

경매 물건의 **회차별 매각 여부와 낙찰가**를 예측하고, 그 낙찰가를 배당 엔진에 넣어 **신보 회수액 분포**를 계산합니다.

- **① 이번 회차에 팔릴 확률** × **② 팔린다면 현재 최저가의 몇 배** → 유찰되면 최저가 ×0.7로 다음 회차 → 최종 낙찰가 분포
- 최종 낙찰가 분포 → 배당 엔진(몬테카를로 1만 회) → 신보 회수액 분포
- 이전 모델(공매 낙찰가율 × 경매 보정계수)은 git 커밋 `6ea474f`에 남아 있습니다.

## 1. 처음 한 번: 환경 준비

macOS
```bash
brew install libomp                      # LightGBM이 맥에서 필요로 하는 라이브러리
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

Windows (명령 프롬프트 또는 PowerShell)
```bat
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
```

## 2. 실행

```bash
cd pipeline
python run_all.py            # 1~7단계 전체 (약 5~10분, 2단계 롤링 CV가 가장 오래 걸림)
python run_all.py 6 7        # 일부 단계만 (앞 단계 결과가 output/ 에 있어야 함)
node ../dashboard/test_engine.js   # (선택) 시뮬레이터 JS 계산 = 파이썬 계산 확인, Node.js 필요
```

- 입력: 물건 정보 + **현재 최저가**(또는 지금까지 유찰 횟수, 비우면 경매 시작 전) + 권리관계·임차인·신보 채권
- 계산: 회차마다 ① 매각확률 × ② 낙찰가 배수, 유찰되면 최저가 ×0.7 → 최종 낙찰가율 P10/P50/P90 → 배당 1만 회 → 신보 회수액
- 위 선택 상자에서 팀이 수집한 실제 경매 사례를 불러오거나, "새 물건 입력"으로 직접 입력. 고친 내용은 그 브라우저에만 저장됨
- 화면은 `dashboard/app.html`, 계산 엔진은 `dashboard/engine.js`

**문서 자동 입력** (`dashboard/doc_parser.js`): 1단계에 PDF를 끌어다 놓거나 글을 붙여넣으면 감정가·용도·소재지·면적·공시지가·건물 정보·등기부·임차인·매각가·집행비용을 채움. 여러 파일을 함께 올리면 합쳐서 채움.
- **현재 최저가·유찰 횟수**: 기일 내역(날짜 바로 뒤 최저가 + 유찰/매각) → 마지막 회차 최저가, 그 앞 유찰 수. 없으면 '최저가(34%) …원' 표시, '유찰 N회' 표시, 최저가 ÷ 감정가 = 0.7ⁿ 순. 최저가가 가려진 예측용 문서면 1단계에 직접 넣으라고 안내 (비우면 경매 시작 전 기준, 검증 안 됨)
- 옥션원 인쇄 PDF: 표 위치까지 써서 정밀하게 읽음 (임차인 표 — 임차인별로 나눠 읽고 문건처리내역상 배당요구일도 반영, 집합건물 대지권, 근저당 일부이전은 원래 근저당 순위로, 건물·토지 등기부에 두 번 나오는 권리는 한 건으로, 경매개시결정의 청구금액은 금액 칸에)
- 그 밖의 양식(법원경매정보 인쇄본, 팀 가상 문서 등): 내용으로 판단 — "날짜 + 등기목적 + 금액" 줄은 권리, "감정가·매각가·소재지·물건 종류…" 옆 값은 물건 정보, "채권계산서·배당요구·교부청구"는 신고 내역
- 감정가가 없고 매각가만 있으면 예측 없이 그 매각가로 배당표만 계산
- 채권계산서 신고액은 메모로만 남김. 근저당 금액은 경매 청구금액이 있으면 그 값, 없으면 최고액 ÷ 1.2 (화면에 '추정' 표시)
- 글자가 들어 있는 PDF를 그대로 읽어 OCR보다 정확하고, 파일은 브라우저 밖으로 나가지 않음. 스캔 이미지 PDF는 지원하지 않음. PDF 읽기 도구(pdf.js 3.11.174)는 `dashboard/vendor/`에 있고 오프라인 파일에 함께 들어감.

왼쪽 메뉴: 입력이 끝난 단계는 초록 ✓, 아직이면 회색 숫자. 3단계는 임차인을 넣거나 "임차인 없음"을 체크하면, 5단계는 한 번 열어 확인하면 완료.

## 5. 분석 프로세스와 배당 규칙

- **시점**: 모든 피처는 예측 시점(매각월 − H개월, 기본 H=1)에 알 수 있던 값만. 지가변동률 지연 = H + 공표 1개월
- **검증**: 월 단위 롤링 CV (평가 월 2026-03~09, 각 fold 는 그 전 달까지 학습) → 설정 고정 → 9월까지 재학습 → 10월 test 한 번
- **경매**: 학습에 쓰지 않음. 공매→경매 차이(배수 수준, 매각확률 기울기)는 388건 안에서 사건 단위 2-fold 교차로 추정해 채점, 실사용값은 전체로 추정해 `output/04_경매시험/auction_shift.json` 에 저장
- **지표**: ① AUC·Brier·log loss·보정 곡선 (정확도·F1 보조) / ② MAE·RMSE·R²·pinball·interval score·구간폭·포함률·하회율 / 회수액 MAE(원)·회수 여부 정확도·F1
- **배당 규칙 (노트북에서 바꾼 것)** — 파이썬(`dividend_engine.py`)과 JS(`dashboard/engine.js`)가 같은 규칙
  - 같은 날 근저당: 금액 비율 안분이 아니라 **을구 순위번호** 순서 (순위번호가 없으면 같은 순위로 안분)
  - **토지·건물 등기부별 배당**: 두 등기부의 근저당 순서가 다르거나 한쪽에만 있는 근저당이 있으면, 매각대금을 토지·건물 감정가 비율로 나누고 등기부마다 순위대로 배당. 공동저당은 각 부동산 경매대가 비율로 분담(민법 368조 1항), 경매대가 = 그 부동산 몫 − 집행비용 몫 − 그 부동산의 선순위(선순위 공동저당은 분담액) − 같은 순위 채권 몫(대법원 2001다66291, 2020다258893), 값이 맞을 때까지 반복 계산. 남은 돈은 그 등기부 근저당의 못 받은 몫부터 채운 뒤 일반채권으로
  - 가압류가 어떤 근저당보다 먼저면: 그 날짜부터 뒤의 권리를 한 풀에서 안분한 뒤 담보권·세금이 후순위 몫을 흡수 (안분 후 흡수). **세금·공과금은 앞선 가압류 몫에서도 흡수.** `ABSORB=false`면 노트북 규칙
  - 세금·공과금은 일반채권보다 앞. 근저당과의 순서는 법정기일을 몰라 압류일로 대신 정함(화면·메모에 경고). 금액 모르는 세금은 체납세금 시나리오, `TAX_FIRST=true`면 당해세로 보고 근저당보다 먼저
  - 소액임차 1/2 한도 = (매각가 − 집행비용) × 한도비율
  - 경매 청구금액: 임의경매 신청 채권자(신보 제외)의 근저당에 순위대로, 각 근저당의 (최고액 − 신보 일부이전 몫)까지 채움. 넘는 금액은 담보 밖. 메모의 '양도 전·양도인·X 근저당 양수·변경 전 상호 X'도 같은 채권자. 이름으로 못 찾고 근저당권자가 한 곳뿐이면 그 근저당에 연결하고 '확인 필요'. 강제경매 신청 채권자의 가압류가 1건이면 청구금액
  - 청구금액이 없는 근저당: (최고액 ÷ 1.2) − 신보 일부이전 몫, 화면에 '추정'. 은행 행에 신보 몫을 빼고 넣은 수집양식은 메모의 '원래 채권최고액 N' / '원래 N억'을 최고액으로 씀
  - 근저당 일부이전(신보 대위변제)은 새 근저당이 아니라 원래 근저당 순위 안의 신보 몫. 원래 근저당 찾기: 같은 접수일 → 같은 순위번호 → 비고의 '을구 N번' → 등기목적·메모의 은행 이름. 은행과 비율로 나눌지 은행이 먼저인지는 `PARTIAL_SUBROGATION` (기본 비율, 멘토 확인 필요. 시뮬레이터 5단계·배당표에서 바꿈)
  - **신보 채권** = 근저당(일부이전 + 신보 자기 근저당) + 신보 가압류 중 근저당 금액을 넘는 부분만 일반채권 한 줄 (같은 구상채권으로 보고 중복 제거). 회수율 분모도 이 합계. 신보 자기 근저당은 신보 임의경매 청구금액이 있으면 그 값(최고액까지)
- **수집양식 엑셀의 선택 열** (없거나 비어 있으면 지금처럼 토지·건물을 합쳐서 계산하고, 메모에 '토지만·건물만'이 있으면 경고)
  - ⑩ 등기부 권리 시트에 `등기부(토지/건물)` 열: 토지 / 건물 / 토지·건물. 공동담보가 등기부마다 접수일·순위번호가 다르면 토지 줄과 건물 줄을 따로 넣으면 한 건으로 합쳐 등기부별 순위로 씀
  - ⓪ 대상 사건 시트에 `토지 감정가(원)` 열: 등기부별 배당의 매각대금 배분 비율. 시뮬레이터는 1단계 '토지 감정가' 칸 (옥션원 PDF는 자동으로 읽음)
- **수집양식 엑셀의 선택 열** (없거나 비어 있으면 토지·건물을 합쳐서 계산하고, 메모에 '토지만·건물만'이 있으면 경고)
  - ⑩ 등기부 권리 시트에 `등기부(토지/건물)` 열: 토지 / 건물 / 토지·건물
  - ⓪ 대상 사건 시트에 `토지 감정가(원)` 열: 등기부별 배당의 매각대금 배분 비율
- `data/` 에는 '수집양식' 엑셀을 **하나만** 두세요. 배당 엔진은 여러 개면 가장 최근에 수정된 파일을 고릅니다.
- 손계산 테스트 T1~T10 (파이썬·JS 같은 값): T6 안분 후 흡수, T7 소액 한도, T9 일부이전·청구금액, **T10 등기부별 배당 — 6번 서부 2023타경35142 25억: 비율 3.70억 / 은행 먼저 0원, 3번 본원 2025타경8468 22억: 9.48억** (`dashboard/fixtures_split.json`)
- 시뮬레이터 배당표의 **낙찰가 직접 입력** 칸: 예측 없이 그 낙찰가로 배당 엔진만 돌려 신보 배당액을 보여줌 (정답 매각가 검증용).

## 6. 폴더

```
data/        입력 데이터 (코드는 읽기만 함)
매각통계/  지역별 지가지수, 지가변동률/
pipeline/    실행 코드 (1~7단계)
dashboard/   HTML 시뮬레이터 템플릿·계산 엔진·검증
output/      실행 결과 (단계별 폴더)
settings.json  배당 계산 가정값
```

## 7. 알아 둘 한계

- 압류재산은 낙찰 3~4개월 뒤 주소·낙찰가가 가려져 ② 학습에는 2026-07~10 압류재산만 있음 → 3~6월 fold 는 기타일반재산만 평가
- 기타일반재산 회차의 13%는 감정가가 없어 ① 에서 빠짐
- ① 의 경매 재보정은 10월 매각공고 388건(전수, 매각 57%)으로 맞춘 값. 9월 법원 매각통계의 회차당 매각율(12~20%)과 차이가 크고 원인은 확인 못 함
- ① 경매 재보정은 Platt + 경매 유찰 횟수(0~5회 이상) 계수. Platt 만 쓰면 신건(유찰 0회)을 17%로 과대예측(실제 0/32) → 유찰 횟수 계수로 8%(교차)·실사용 약 5%로 낮춤
- 경매 시작 전(최저가 = 감정가) 예측은 검증되지 않음 → 시뮬레이터는 최저가를 비우면 경고 표시
- 배당: 일부대위 규칙(비율 안분 / 은행 먼저)은 멘토 확인 전 → 시뮬레이터 민감도 표에 두 규칙을 나란히 표시. 근저당 실채권(÷1.2 추정), 세금, 집행비용(1%)은 가정값이고 실제 배당표와 대조한 적 없음
- 경매 미매각 168건에 유찰 외 사유(변경·취하)가 섞여 있을 수 있음
- 6단계·시뮬레이터의 경매 보정값은 388건 전체로 추정 → 배당 50건 결과를 실제와 비교한 값은 성능 점수가 아님 (성능은 4·5단계 교차 추정 값)
- 시뮬레이터의 배당 계산은 '팔린다면' 기준. 8회차 안에 안 팔릴 확률은 따로 표시
- 경매 평가는 2026-10 한 달 안의 검증. 학습에 안 쓴 달로 하는 검증은 11월 경매 결과가 필요
- `data/auction_feat_cache.jsonl`(0단계 API 조회 캐시)은 최종 `auction_features.csv`보다 오래돼 일부 주소가 빠져 있음. 0단계는 사건을 추가할 때만 인증키를 넣고 실행
